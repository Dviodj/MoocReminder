# 使用人数统计（发布者配置说明）

程序里有一个**默认关闭**的「参与使用人数统计」开关。用户勾选后，程序每天最多一次在发布者仓库的
一个 issue 上留一条评论，内容是「本机随机生成的 16 位编号 + 当前版本号」。没有服务器，没有数据库，
发布者看那个 issue 里的评论条数就知道大概有多少台设备在用。

## 为什么不用服务器

这个程序承诺数据只存在用户本机，加一台常驻服务器就要一直维护、一直保证它的安全，代价远大于收益。
GitHub 的 issue 页面本身就是个公开、可查、随时能关掉的地方。

## 为什么是一台设备一条评论

issue 正文是共享的：两个用户同时启动会互相覆盖对方那一行，而且改写别人的正文需要更宽的权限。
一条评论由它自己的那台设备创建、之后只做修改，彼此不会冲突。程序读评论列表时会带上写入凭据，
因为**匿名读取这个接口的响应有最长一分钟的缓存**——刚写完立刻匿名读，看到的还是旧页面，
于是会再发一条重复评论（这个问题在真实环境里出现过并已修好）。

## 发布者怎么配置

1. 在仓库里建一个 issue（建议标题 `MoocReminder 使用统计（程序自动填写，请勿关闭）`），
   记下它的编号，地址形如 `https://api.github.com/repos/<账号>/<仓库>/issues/<编号>`。
2. 建一个**只给这个仓库、只需要 issue 写权限**的令牌（fine-grained token：Repository permissions →
   Issues → Read and write）。不要用带全仓库权限的经典令牌。
3. 复制 `usage_report.example.json` 为 `usage_report.json`，填进 `github_token` 与 `issue_url`。
   这个文件**已在 `.gitignore` 里**，和 `email_sender.json` 一样不会被提交——公开仓库里出现令牌，
   GitHub 会立即吊销它。
4. 打包：`python tools/package_source.py --with-runtime` 会把 `usage_report.json` 一起打进便携包。
   **没有这个文件也能正常打包**，只是统计功能不可用（程序不会发送任何东西）。

## 停止统计

把那个 issue 关掉即可。程序读到 `state: closed` 就不再写入，并在本地界面说明「统计已停止」。
已经留下的评论可以一并删掉。

## 用户在界面上看到什么

**提醒设置** 里有一个「参与使用人数统计」复选框，默认不勾。勾选时程序生成一个随机编号保存在本机，
取消勾选会把编号一并删掉。用户可以在那个公开页面上看到自己留下的那一行。
