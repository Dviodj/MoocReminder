# 发件邮箱配置（发布者）

普通用户只填自己的**收件**邮箱，提醒由这里的发件邮箱统一发出。
用户不需要了解服务器或授权码。

## 授权码怎么获取

**程序内自带图文教程**：打开「邮件提醒」→ 勾选「高级选项」→ 点 **如何获取授权码？**，
会按填入的发件邮箱域名显示对应服务商的步骤（QQ 邮箱 / Foxmail / 163 / 126），
包含官方入口路径、服务器与端口、常见问题排查。教程内容在 `src/mail/mail_guide.py`。

以 QQ 邮箱为例的要点（依据腾讯官方帮助页
[如何开启 POP3/SMTP/IMAP 服务并获取授权码](https://help.mail.qq.com/detail/0/1087)）：

1. 登录 QQ 邮箱网页版 → 顶部 **设置** → **账号与安全**
2. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV 服务** 区域，点旁边的 **开启**
3. 用绑定的手机号发送指定短信，回到页面点 **我已发送**
4. 页面弹出 **16 位授权码** —— 只显示一次，当场复制
5. 服务器 `smtp.qq.com`、端口 `465`、加密方式 `SSL`（程序会自动填）
6. 日后在 **设备管理 → 授权码管理** 里可停用或重置

> 注意：QQ 邮箱现在把这个入口放在「账号与安全」，不再是旧版的「设置 → 账户」。
> 界面改版时以官方帮助页为准。

## 怎么配

1. 把 `email_sender.example.json` 复制为 **`email_sender.json`**（同目录）。
2. 填入真实值：

```json
{
  "sender": "reminder@example.com",
  "server": "smtp.example.com",
  "port": 465,
  "security": "ssl",
  "password": "该邮箱的授权码"
}
```

`security` 取 `ssl`（常用 465）或 `starttls`（常用 587）。
留空或删除某一项，该字段就没有默认值，用户必须在高级选项里自己填。

3. `email_sender.json` **不会被提交**（已在 `.gitignore` 中排除），
   因为里面有授权码。仓库里只保留空的 `email_sender.example.json`。

4. **装包前先验证**——填错授权码会让**所有**用户静默收不到提醒，所以别靠猜：

   ```powershell
   python tools/check_sender.py                    # 只报告配置状态，不打印授权码
   python tools/check_sender.py --to 你的邮箱      # 真发一封测试邮件
   ```

   第一行会列出每个字段是否填好（授权码只报长度）；第二行以该邮箱真实投递一封，
   收到即说明授权码与服务商设置都对。打包器也会在缺 `sender` 或 `password` 时拒绝出包，
   但它只能检查"填了没有"，不能检查"能不能用"，所以这一步仍然要做。

## 请务必了解的风险

本程序完全在本机运行，没有服务器中转，因此**发件邮箱的授权码必须随发布包一起分发**，
用户端才能发信。这意味着：

- **拿到发布包的人可以提取出这个授权码**，并以该邮箱的名义发信。
- 请不要使用个人常用邮箱，而是**专门注册一个发信邮箱**。
- 在该邮箱服务商处**开启发信量限制**，万一泄露也能把影响限制住。
- 打包前确认 `email_sender.json` 里没有你不希望公开的内容——它会进入发布包。

如果以后改为服务端发信，授权码就可以只留在服务器上，用户端不再需要它。

## 用户能否改

可以。用户在「邮件提醒 → 高级选项」里填了发件邮箱或服务器，就以用户的为准；
留空的项沿用本配置。授权码同理：用户填了自己的就用用户的。
