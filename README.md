# MoocReminder v0.2.2

把 MOOC 作业的截止时间集中起来，在忘记提交之前提醒你。

## 为什么开发这个程序

我们也经常被忘交 MOOC 作业这件事困扰。

同时上几门课时，作业和测验分散在不同课程页面里，截止时间也各不相同。原本想着“过两天再做”，一忙起来就忘了；等到重新打开课程，才发现提交入口已经关闭。明明打算完成，却因为没记住截止时间错过了作业。

因此，我们开发了 **MoocReminder**：自动检查课程中的作业与测验，把截止时间整理到一个窗口，并在到期前提醒。希望少一些“怎么已经截止了”的懊恼，让大家更容易安排自己的学习时间。

![MoocReminder 界面](docs/images/overview.png)

## 目前能做什么

- **集中查看截止时间**：读取中国大学 MOOC 和校内 SPOC 的作业、测验，按截止时间整理。
- **定期检查与提前提醒**：默认每 30 分钟检查，提前 3 天、1 天、3 小时弹窗提醒。
- **按自己的节奏设置**：支持修改检查间隔、提醒时间、课程主页及补充作业链接。
- **记录完成情况**：支持搜索和本地完成标记，完成后可停止该项提醒。
- **保留已有记录**：单门课程读取失败时保留上次结果，登录配置按账号保存在本机。
- **直观的启动过程**：独立启动窗口显示当前阶段和进度，支持取消、失败重试，并自动创建桌面快捷方式。
- **解压即用**：内置 Python 运行环境与网页组件，换一台电脑无需安装 Python、.NET 或 WebView2。
- **新版本与公告自动送达**：启动后在后台检查是否有新版本，发布说明里的公告也会显示在总览页；失败静默，不上传任何数据。

主窗口采用 macOS 风格，程序运行在 Windows 上；通过内置的 QtWebEngine 窗口登录官网，登录窗口与后台检查共用本地配置。

## 未来希望扩充的方向

现在的提醒发生在电脑上。接下来，我们希望把提醒送到更常看的地方，并进一步打通任务处理流程。

- [ ] **微信提醒**：把即将到期的作业推送到微信，离开电脑后也能及时收到提醒。
- [ ] **邮箱提醒**：支持邮件通知和作业汇总，让截止时间进入日常查看的收件箱。
- [ ] **domooc 联动与自动完成**：探索接入 [domooc](https://domooc.top/domoocreadme)，将作业检测、截止提醒与自动完成流程衔接起来，并同步处理后的任务状态。

这些方向目前处于规划阶段，具体接入方式会逐步验证和完善。我们的长期目标是让“发现任务、收到提醒、及时处理、更新状态”形成连贯的流程，减少遗漏和重复操作。

## 快速开始

### 运行环境

- Windows 10 / 11，64 位。
- **不需要预先安装任何东西**：Python 运行环境与网页组件都随包分发（内置 CPython 与 QtWebEngine）。
  不再需要 .NET Desktop Runtime，也不再需要 WebView2 Runtime。

### 使用步骤

1. 下载 **便携包**
   （[MoocReminder-v0.2.2-offline-x64.zip](https://github.com/Dviodj/MoocReminder/releases/download/v0.2.2/MoocReminder-v0.2.2-offline-x64.zip)，
   压缩包约 248 MB，解压后约 669 MB）并解压出完整文件夹，解压即用；想自己装依赖的话，
   也可以用 [源码包](https://github.com/Dviodj/MoocReminder/releases/download/v0.2.2/MoocReminder-v0.2.2-source.zip)。
2. 双击 **启动MoocReminder.bat**，启动窗口会显示进度，随后弹出登录窗。
3. 第一次使用点 **注册账号**，只填一个账号名称（例如「主账号」）即可进入。
4. 进入后点 **绑定慕课与邮箱**，填入课程主页链接 `https://www.icourse163.org/home.htm?userId=你的数字账号#/home/course` 和接收提醒的邮箱。这两步完成前无法检查作业。
5. 点击 **连接慕课**，在打开的官网窗口中登录。
6. 返回主窗口点击 **检查作业**，之后保持程序运行。

账号、慕课绑定与邮箱设置只需做一次，之后每次打开只需在登录窗选择账号进入。

程序**关掉窗口不会停止监测**：关闭按钮是最小化到系统托盘，提醒照常发出。要真正退出，请右键托盘图标选 **退出 MoocReminder**（也可以在那里临时暂停提醒）。关机或休眠期间不会提醒。默认检查当前学期，历史学期可在设置中启用。

重复双击启动图标不会开出第二个程序：如果已经在运行（例如开机自启动已经在托盘里），会直接把那个窗口叫到前面——两个进程同时跑会把同一批提醒发两遍，所以程序只允许一个实例。

### 开机自动启动

开机自启动**默认关闭**，需要你自己同意：首次进入后总览页会出现一张提示卡询问一次，回答后不再打扰；之后随时可以在 **提醒设置** 里勾选或取消。

开启后，登录 Windows 就会在系统托盘里静默运行（不弹窗）。启动项写在 Windows 的「启动」文件夹里，指向程序自身，因此**项目移动或改名后会自行修正**；如果那个位置已经有**其他程序的同名启动项**，程序绝不会覆盖或删除它。

### 账号

启动时会先弹出登录窗，选择账号进入；没有账号就点 **注册账号**。

- **账号只存在这台电脑上**：不需要密码（账号名就是标识），也不会把任何数据上传到服务器。因此换一台电脑需要重新注册，作业记录不会同步。
- 每个账号各自绑定**自己的慕课账号、邮箱、作业列表与完成标记**，互不干扰；检查间隔、提前提醒小时数这类偏好由所有账号共用。
- 侧栏的 **当前账号** 可以随时切换账号，或选择「添加账号…」再建一个。切换后立即恢复该账号上次的内容，**不用重新登录慕课**。
- 新账号默认沿用当前账号的邮箱与授权码，不用重填；慕课绑定需要各自填写。

以后若要把账号放到服务器上（跨设备登录、关机也能收到提醒），账号数据层已经独立成 `src/domain/profiles.py`，可以替换实现而不改界面。

### 邮件提醒

主界面右上角的 **邮件提醒** 按钮随时可点，**不需要先登录慕课**。**普通用户只需要填自己的邮箱地址**——提醒由程序预置的发件邮箱统一发出，不需要了解邮件服务器或授权码。填好后可先发一封测试邮件确认。

需要自己指定发件邮箱时，选择 **使用我自己的发件邮箱**，填入发件邮箱、服务器与授权码；留空的项仍使用程序预置值。

提醒会发在两类时机：作业临近截止的提醒窗口（默认提前 72、24、3 小时），以及在「汇总发信时刻」填写的固定时刻（例如 `08:00,20:00`）发一封作业汇总。汇总的**频率**可以选：**每天**（默认）、**每周一次**（自己挑星期几）或**每 N 天一次**（2–30 天）；跨天的频率若当天没赶上（关机、休眠或没开程序），下一次打开时会补发一次。**程序需要在运行**，关机、休眠或退出程序期间不会发信。

### 更新与公告

程序启动后会在后台检查一次是否有新版本；之后**每 24 小时**再检查一次。发现新版本时，总览页会出现一张卡片，点 **下载新版本** 打开发布页面。也可以随时在 **提醒设置 → 检查更新** 手动检查。

- 检查过程**完全静默**：没有网络、被墙、或返回内容异常时，都只是不显示卡片，不会弹出任何错误窗口。
- 读的是 GitHub 上**公开发布页**（不调用需要配额的接口）。这一点有实际原因：GitHub 的接口对未认证请求按 IP 限流每小时 60 次，一整个宿舍或校园网出口的多个用户会互相挤掉配额，而且失败是静默的，问题很难被发现。发布页不受这个限制。
- 新版本内容是**覆盖式升级**：把新的程序文件夹解压出来，覆盖旧文件夹即可。`data` 文件夹（或 `%LOCALAPPDATA%/MoocDeadlineReminder`）里保存着账号、登录状态与完成标记，**请保留不要删掉**。
- 公告写在发布说明里：发布说明中如果有一段 ```` ```mooc-reminder-announcements ```` 包裹的 JSON，就会作为公告显示在总览页；点 **知道了** 之后不再出现（按公告的 `id` 记）。公告里加 `"pinned": true` 会让它排在其他公告前面（适合欢迎语、重要通知），但对已经点过 **知道了** 的人依然不再出现。`"level": "warning"` 会让标题变成橙色。
- 如果不想让程序联网检查，在 **提醒设置** 里取消 **自动检查更新与公告**；之后只有在点 **检查更新** 时才会请求。

**关于隐私**：检查更新与公告只向 GitHub 的公开页面发起读取请求，**不上传任何数据**——没有账号标识、没有机器标识、没有使用记录，也没有令牌。所有用户的请求内容完全相同。程序的账号、作业记录与邮件设置始终只保存在本机。

### 登录慕课的两种方式

点击 **连接慕课** 后可以选：

1. **在内置窗口中登录**（默认，适合大多数情况）：打开一个内置浏览器窗口，在里面完成登录。
2. **粘贴浏览器里的 Cookie**（备用）：内置窗口打不开或登录不上时使用。在已登录慕课的浏览器里按 F12 → 网络（Network）→ 刷新页面 → 点第一个请求 → 找到「Cookie」请求头，把内容整段复制进来即可。程序只读取慕课相关的 Cookie，其余内容会被忽略；粘贴后会立即校验登录是否有效，无效会明确报错而不是静默失败。

两种方式都只把登录状态保存在本机。

### 提示“无法验证发布者”时

这是 Windows 对**从网上下载的文件**的常规提示，不是病毒警告：发布包里的文件带着“来自网络”的标记，Windows 会先拦一次。**点“运行”即可**——启动脚本第一步就会自动清除整个文件夹的这个标记，之后再启动不再弹提示。

程序未做数字签名，所以这一次提示无法由程序自身避免。如不希望任何提示，需要为发布包购买代码签名证书。

官网未明确显示提交状态的条目会标为“请核对”。程序读取的是作业提交截止时间，互评截止时间不会列入提交提醒。

需要较小的下载或进行开发时，也可使用 [v0.2.2 源码包](https://github.com/Dviodj/MoocReminder/releases/download/v0.2.2/MoocReminder-v0.2.2-source.zip)。源码包不含内置运行环境，需要机器上已有 64 位 Python 3.11–3.15，并由使用者自行安装依赖；便携包把这些都放在发布前完成。

## 本地数据与问题排查

设置、作业缓存和完成标记优先保存在 `%LOCALAPPDATA%/MoocDeadlineReminder`；该目录不可写时，使用项目内的 `data` 文件夹。登录配置保存在数据目录下的 `web-profiles/<账号>`。

个人登录配置和作业缓存不上传仓库，也不包含在发布包中。换电脑后需要重新登录。启动失败时可查看 `.launcher-state/startup.log`；读取失败时可在主窗口的 **连接详情** 查看错误。

发布包内置 CPython 与 Qt（含 QtWebEngine），随包组件的版本与来源记录在 `.build/runtime-bundle/bundle.json`，CPython 压缩包与各 wheel 的 SHA-256 在构建时校验。第三方许可证保留在各组件及 `.dist-info` 目录中；Qt 采用 LGPL-3.0，正文随包提供在 `licenses/`。该目录无需提交到 GitHub 源码仓库。

## 仓库结构

仓库根目录只放被版本控制的源码和发布入口；构建、发布与实测产物统一收在 `.build/` 下（该目录无需提交，可随时删除）：

| 路径 | 内容 |
| --- | --- |
| `src/` | 全部源码，按职责分在 `domain/`（规则与数据）、`mail/`（邮件提醒）、`web/`（浏览器）、`ui/`（界面）、`system/`（启动与环境）里 |
| `tools/` | 发布者用的构建脚本（生成便携包与 ZIP），用户运行不到 |
| `启动MoocReminder.bat`、`launch.bat`、`launch.vbs` | 启动脚本，留在根目录方便双击 |
| `assets/`、`docs/`、`tests/` | 图标、验证记录与结构说明、自动测试 |
| `LICENSE`、`THIRD-PARTY-NOTICES.md`、`licenses/` | 本项目 MIT 许可证、随包第三方组件声明、Qt 的 LGPL/GPL 正文 |
| `.launcher-state/` | 本机启动日志与运行缓存，按已发布离线包的布局保留在根目录 |
| `.build/` | `runtime-bundle/`（解压好的运行组件）、`wheel-cache/`、`releases/`、`temp/`、`artifacts/` |

各文件的用途与当前运行链路见 [docs/STRUCTURE.md](docs/STRUCTURE.md)。

## 开发与验证

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

开发环境约 760 MB（QtWebEngine 占大部分）。`test_site` 与 `test_qt_reader` 会真实渲染页面，请在有图形界面的 Windows 会话运行，不需要联网。

当前开发状态为 **284 项通过**（`python -m unittest discover -s tests`）。复现完整数量需要 64 位 Python 3.11–3.15 并安装 `requirements.txt`：缺少 `PySide6-WebEngine` 时 `test_qt_reader` 与 `test_site` 会导入失败（该模块由 Qt 单独分发，不在 Essentials 或 Addons 内）。桌面快捷方式与开机自启动相关的测试需要 Windows 与 PowerShell。v0.1.1 发布时通过 83 项。

发布者制作便携包：先运行 `python tools/bundle_runtime.py` 生成内置 Python 与 Qt 组件，再运行 `python tools/package_source.py --with-runtime` 打出 ZIP。普通用户无需执行构建步骤。真实的“连接慕课”按钮需要人工验证时，直接运行程序点一次即可。

课程读取依赖官网当前页面结构。登录失效或网站结构变化时，程序会显示错误并保留缓存。
